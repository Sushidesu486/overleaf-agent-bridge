## Runtime and implementation decisions

- Base: Overleaf CE 6.3.2, upstream image digest `sha256:d17e196b04222837440b5efb2890864eb200a2e9341e434c0e6bd57a61011cbb`; revision `370f4763da4bc910da8309c9a71c85ecbe39f6a7`.
- Derived image: `overleaf-agent-lab:6.3.2-dev`, local image ID `sha256:0fc74d0795f528b7e237cbcb70ce4e8ec2daa141326779d0736eef63df285725`. Dockerfile and source-hash checks define how to reproduce the extension on this base. The preceding History image was `sha256:bf520465740e079482e587f8437c02009a674c5a7d9523f6b6e46b6ae2f88cfa`; the first personal-URL image was `sha256:0a14f3de38af03bd996e5994705f49379b0163d9e94f88ec805b603dbd0819b5`.
- TeX Live 2026, MongoDB 8.0.34 (single-member replica set), Redis 7.4.12/AOF. Baseline versions were verified at 2026-11-05T17:24:53+08:00; this milestone keeps those base dependencies.
- Frontend build: restore the pinned web workspace’s development dependencies from the image’s Yarn cache with networking/scripts disabled, then rebuild every entrypoint and the asset manifest together. Copy only the generated assets and compiled Pug page into the runtime stage, retaining its production dependencies. `patches/frontend.py` guards module registration, the rail tab type and the main stylesheet against known source hashes.
- The first implementation runs a separately bundled MCP module inside Overleaf Web. This gives the authorization code direct access to native user/project permission checks and avoids creating unrestricted user sessions. A separate gateway can be introduced if operational needs justify it later.
- Nginx suppresses credential-route access/error logs and forwards a fixed internal URL. The extension consumes and removes the credential header. HTTP MCP is stateless and revalidates every request. Grant and edit-operation metadata are in the new `agent_grants` and `agent_operations` collections within this lab database.
- Compile diagnostics reuse the pinned native UI parser, with a source hash checked and TypeScript erased by the image's Node 24 runtime. The native CLSI download helper receives an omitted shard argument for CE's `null` shard result. `agent_compile_builds` holds only user/project/build routing metadata with a 24-hour TTL; log reads recheck current read access and never accept caller-selected routing URLs. Native output may expire earlier. Reads cap source data at 2 MB and response pages at 32,000 characters; metadata/fetch failures preserve the compile result with a safe unavailable reason.
- Sidebar transport uses an outbound SSE command stream plus HTTP event POSTs, and browser SSE snapshots with native login/CSRF routes. This replaces the proposed WebSocket transport while keeping one existing HTTP entrypoint. Live routing currently requires a single Web worker. Durable chat metadata is in `agent_chat_pairings`, `agent_chat_connections`, and `agent_chat_sessions`; backups must include them. Connection revocation also revokes its MCP grant.
- ACP execution is local stdio. On POSIX the connector owns a process group and terminates it on shutdown, with a referenced forced-kill deadline. Permission prompts are serialized, consecutive turns are queued, and browser snapshots only advance by revision. Session-length and message limits bound stored transcripts.
- Independent Docker volumes/network; only `127.0.0.1:18080` is published, no database port or GPU. Stop with `docker compose stop` to preserve data.
